# Firebase (план Spark: вход, профиль, ник, рекорды, облако)

Онлайн-часть необязательна: без файла `firebase.cfg` игра полностью офлайн (локальный
профиль, ник на устройстве, туториал), кнопка «Рекорды» скрыта. Подключение — REST API
Firebase из GDScript (`scripts/online.gd`, autoload `Online`), без нативных плагинов.

**Только бесплатный план Spark: Cloud Functions нет и не будет.** Всё, что должен гарантировать
сервер (уникальный ник, чужие данные, размеры и типы полей, «рекорд только растёт», лимит
смены ника), проверяют правила `firestore.rules`. Клиент — не граница безопасности. Подробно:
`docs/ACCOUNTS.md`; какие данные собираются: `docs/PRIVACY.md`.

> **Статус:** живой проект Firebase не создавался, вход/правила на нём **не проверялись**.
> Проверено только: правила на локальном эмуляторе Firestore (`firebase/rules-tests`) и клиент
> на поддельном сервере (`tests/test_accounts.gd`). Чек-лист проверки на живом проекте — ниже.

## Что хранится

| Данные | Где | Когда |
|---|---|---|
| Анонимный id (uid, Firebase Auth) | Authentication | первый запуск с `firebase.cfg` |
| Почта и пароль (хеш пароля хранит Firebase Auth, игра пароль не хранит) | Authentication | только если игрок сам привязал почту |
| Прогресс, настройки, флаги онбординга | `users/{uid}` (приватно) | синхронизация |
| Публичный ник | `publicProfiles/{uid}`, `nicknames/{ключ}` | выбор/смена ника |
| Рекорд осады и ник рядом с ним | `leaderboards/level_N/scores/{uid}` | новый рекорд |
| Старт забега осады (уровень + серверное время) | `runs/{uid}` | начало бесконечной осады |
| Результат Испытания дня: ник, волна, серверное время | `daily/{yyyy-mm-dd}/scores/{uid}` | конец попытки дня |
| Бонусные звёзды дня (`progression.dailyStars`) и открытые достижения (`achievements`, битовая маска) | `users/{uid}` | синхронизация профиля |
| Кошелёк самоцветов (`wallet`: итоги, ключи наград, покупки косметики, надетое) и серия дней (`streak`) | `users/{uid}` | синхронизация профиля |
| Время последней смены ника (без самого ника) | `nicknameTrace/{uid}` | выбор/смена ника |
| Прогресс старых версий | `saves/{uid}` | только чтение/миграция, потом удаляется |

Почта собирается **только** если игрок привязал её в Профиле (нужна для входа на другом
устройстве и сброса пароля); в Firestore и на устройство она не пишется. Ни рекламы, ни
аналитики поведения, ни геолокации. Исключение: Firebase Crashlytics (отчёты о сбоях, включён
по умолчанию, отключается в настройках; только Gradle-сборка Android) — `docs/ANDROID_BUILD.md`,
`docs/DEBUG_ANDROID.md`, `docs/PRIVACY.md`.

## Создание проекта (один раз, ~15 минут, делает владелец)

Ничего из этого агент/CI не делает: проект и деплой — за вами.

1. <https://console.firebase.google.com> → **Add project** → имя `bimbleguard` →
   Google Analytics **выключить**. Платёжный аккаунт не подключать: остаётся план **Spark**.
2. **Build → Authentication → Get started → Sign-in method** → включить **Anonymous** и
   **Email/Password** (переключатель «Email link (passwordless sign-in)» не включать: игра его
   не использует). Другие провайдеры не включать.
   Защита от перебора почт (*Authentication → Settings → User actions → Email enumeration
   protection*) может быть включена или нет — игра работает с обеими настройками. Язык письма
   сброса пароля: **Authentication → Templates → Password reset**; язык и текст письма
   подтверждения почты (отправляется после регистрации, игра им не блокируется):
   **Authentication → Templates → Email address verification**.
   Без включённого Email/Password кнопки привязки и входа отвечают «Вход по почте сейчас
   недоступен» (`OPERATION_NOT_ALLOWED`), остальное работает.
3. **Build → Firestore Database → Create database** → режим **Native**, регион
   (например `eur3`/`europe-west1`; регион потом не изменить) → **Production mode**.
4. Установить CLI и войти (у вас — на своём компьютере):
   ```bash
   npm i -g firebase-tools        # нужен Java 21+ только для эмулятора
   firebase login
   firebase use --add             # выбрать проект; создаст .firebaserc (не коммитится)
   ```
5. Задеплоить **только правила и индексы** (функций нет):
   ```bash
   firebase deploy --only firestore:rules,firestore:indexes
   ```
   Либо вставить `firestore.rules` во вкладку **Firestore → Rules** → **Publish**.
   `firestore.indexes.json` пуст: составных индексов не нужно (рекорды сортируются по одному
   полю `wave`).
6. **Project settings → General → Your apps → Web (`</>`)** → зарегистрировать приложение →
   из `firebaseConfig` взять `apiKey` и `projectId`.
7. Скопировать `firebase.example.cfg` в `firebase.cfg` и вписать их. Файл не коммитится, но
   попадает в APK (`include_filter` в `export_presets.cfg`).
8. **Ограничить API-ключ** (Google Cloud Console → APIs & Services → Credentials → ключ
   «Browser key»): *API restrictions* → только **Identity Toolkit API**, **Token Service API**
   и **Cloud Firestore API**. Ограничение по приложению Android для REST из Godot не
   применимо (запросы не несут сертификат), поэтому ключ — идентификатор проекта, а не секрет;
   защита — правила и квоты.
9. Деплой правил повторять после каждого изменения `firestore.rules`.

`apiKey` веб-приложения — не секрет. **Никогда** не кладите в клиент сервисные ключи
(`serviceAccount*.json`), токены администратора и секреты.

## Таблица Испытания дня (`daily/{day}/scores/{uid}`)

Клиент: `Online.submit_daily(день, волна)` (очередь в секции `[daily_queue]` сохранения, одна
попытка отправки за вызов и при запуске игры; отказ правил — запись отбрасывается),
`Online.fetch_daily(день)` (топ-10, сигнал `daily_loaded`). Правила (`firestore.rules`):
только владелец; день в пути — сегодняшняя дата UTC **по `request.time`** (плюс день-вчера в
первый час после полуночи для забега, начатого до неё), формат `yyyy-mm-dd`; поля ровно
`name, wave, updated`; `name` — свой ник или `Рыцарь`; `wave` целое 1..499 и **только растёт**;
`updated == request.time`; чтение одного документа открыто, листинг не больше 100; удаление —
владельцу (удаление аккаунта сносит записи за сегодня и вчера). В отличие от `leaderboards`
здесь нет часов забега: волну нельзя проверить на сервере, это общая граница Spark; проверка
реплеем (`header.daily` + журнал) — следующий этап. Коллекции `daily` нужен только листинг по
`wave`: одиночное поле, индекс создаётся автоматически. Тесты: `firebase/rules-tests`
(эмулятор), клиент — `tests/test_daily_online.gd` (поддельный сервер, `tests/fakes.gd`).
Расход квот: одна запись на игрока в сутки + 1 листинг по открытию окна.

В `users/{uid}` добавлены необязательные поля: `achievements` — целое 0..2^31-1 (бит на достижение,
таблица `resources/achievements.json`; карта по ключам не годится — упирается в лимит 1000
выражений правил) и `progression.dailyStars` — целое 0..10. Правила развёрнуты **не** были:
перед релизом нужен `firebase deploy --only firestore:rules` (делает владелец).

### Кошелёк и серия в `users/{uid}` (schemaVersion 3)

`wallet: {gems, earned, spent, claims, buys, equipped}`: три целых и три строки вида
`ключ=значение;ключ=значение` (`Wallet.to_cloud`). Баланс **выводится** (gems = earned - spent), а
слияние устройств идёт по ключам (максимум на ключ), поэтому награда не выплачивается дважды, а
покупка не теряется. Правила (`walletOk`): ключи только из белого списка, числа целые, gems =
earned - spent (или 0 при перерасходе), `earned <= 20000 + 700 * (дней с создания аккаунта + 1)`
(разовая сумма за прогресс до появления валюты плюс дневной лимит; границы в
`resources/economy.json` `rules_bounds`), строки только `[a-z0-9_:=;-]`, длины 12000/3000/600.
`streak: {last, len, best, grace}` проверяется `streakOk`. Правила кошелька: 4 теста в
`firebase/rules-tests/firestore.wallet.test.js` (свой projectId: файлы тестов идут параллельно);
в `database.rules.json` у игрока комнаты появилось необязательное `skin` (≤32, `[a-z0-9_]`).
Правила **не развёрнуты** (деплой делает владелец). Удаление аккаунта удаляет `users/{uid}`, а с ним
и кошелёк.

## Квоты Spark и риски

Лимиты Spark (на момент написания; сверьте с <https://firebase.google.com/pricing>): Firestore
примерно 50 тыс. чтений, 20 тыс. записей и 20 тыс. удалений в сутки, 1 ГиБ данных. Клиент
экономит: синхронизация — при запуске и при изменении прогресса, рекорд — только новый.
При превышении квоты запросы получают 429/403: игра остаётся рабочей офлайн, интерфейс
показывает «Не синхронизировано». Если игра выйдет в широкий релиз — переходите на Blaze с
бюджетом и оповещением; код для этого менять не нужно.

## Тесты правил на эмуляторе

Требуются Node 20+ и **Java 21+** (firebase-tools 15 не стартует эмулятор на Java 17).
```bash
cd firebase/rules-tests && npm install
export PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH   # macOS/Homebrew; иначе свой JDK 21
npm test        # поднимает эмулятор Firestore (порт 8189) и гоняет firestore.rules.test.js
```
Покрыто (31 тест): чужие чтение/запись/удаление, поля и типы `users`, уникальность ника
(регистр, `ё/е`, гонка двух игроков), смена ника атомарным батчем + лимит 24 ч, «один ник на
игрока», политика символов по `tests/nickname_cases.json` и всем разрешённым буквам
(`tests/nickname_letters.json`), удаление аккаунта, рекорды (только вверх, имя, не быстрее часов волн по `runs/{uid}`), след смены ника
(`nicknameTrace`: удаление профиля не сбрасывает лимит 24 ч), `saves`,
запрет по умолчанию. Эмулятор — не живой проект: правила на нём те же, но квоты, App Check и
сетевые ошибки он не воспроизводит.

## Проверка на живом проекте (после шагов выше)

Не выполнялась. Руками, на устройстве или в редакторе с `firebase.cfg`:

1. Первый запуск онлайн → в Authentication появился анонимный пользователь; выбрать ник →
   в Firestore есть `nicknames/<ключ>`, `publicProfiles/<uid>`, `users/<uid>`.
2. Второй игрок (другое устройство/переустановка) берёт тот же ник (любой регистр) → «имя
   занято».
3. Сменить ник → через <24 ч повторная смена отказывает; старый `nicknames/<ключ>` удалён.
4. Бесконечная осада → рекорд в `leaderboards/level_N/scores/<uid>`; «Рекорды» → топ-10.
5. Профиль → «Удалить аккаунт» → пропали все документы `<uid>` и пользователь в
   Authentication; игра стартует как с нуля.
6. Режим полёта: выключить интернет → игра играбельна, «Не синхронизировано», после
   возврата сети синхронизируется.
7. Консоль → Firestore → Usage: убедиться, что нет всплесков чтений/записей.

### Чек-лист входа по почте (живой проект, не выполнялся)

Нужен проект с включённым Email/Password. Проверять на тестовой почте, которую не жалко.

1. Профиль (гость) → «Привязать почту» → почта и пароль ≥ 6 символов → в Authentication тот
   же пользователь получил почту, uid не изменился, прогресс на месте.
2. Другое устройство (или переустановка): экран ника → «У меня уже есть аккаунт» (или
   Профиль → «Войти по почте») → вернулись звёзды, рекорды и ник аккаунта; гость этого
   устройства остался осиротевшим пользователем в Authentication.
3. Неверный пароль → «Неверная почта или пароль»; серия неверных → «Слишком много попыток»
   (`TOO_MANY_ATTEMPTS_TRY_LATER`).
4. «Забыли пароль?» → письмо пришло, ссылка ведёт на страницу Firebase, новый пароль работает.
5. «Выйти из аккаунта» → игра стартует с нуля, вход по почте возвращает прогресс.
6. Давний вход → «Удалить аккаунт» просит «Войти заново», после входа удаление проходит
   (`CREDENTIAL_TOO_OLD_LOGIN_AGAIN`).
7. Первый запуск на чистом телефоне: «Добро пожаловать» → «Создать аккаунт» (почта, пароль, ник) →
   в Authentication появился пользователь с почтой (не анонимный); пришло письмо подтверждения;
   «Профиль» показывает «Почта не подтверждена», после перехода по ссылке и повторного открытия
   профиля — «Почта подтверждена ✓». Закрыть и открыть игру: вход без экранов, прогресс сразу на
   месте. Режим самолёта: игра открывается и играется, профиль говорит «Не в сети · синхронизируется
   позже».
8. «Играть без аккаунта» → играть → после первой победы на карте карточка «Не потеряй прогресс» →
   «Создать аккаунт» — тот же uid, прогресс на месте (`accounts:update`, а не `signUp`).
9. Письма (сброс пароля, подтверждение) ограничены квотами Firebase: при лимите игрок видит «Слишком много
   попыток». Размер квоты на Spark смотрите в консоли, здесь не проверялся.

## Кооператив: Realtime Database (необязательно)

План, протокол и квоты: `docs/MULTIPLAYER.md` (разделы 12a, 12b). **Состояние на 2026-10-15:** Realtime Database в проекте `bimbleguard` включена (по сообщению владельца), правила `database.rules.json` задеплоены. Эта ветка живой проект не трогала (ни запросов, ни деплоя); всё проверено на эмуляторе. Включается владельцем:

1. **Build → Realtime Database → Create database** (регион рядом с игроками; для `europe-west1`
   URL вида `https://<проект>-default-rtdb.europe-west1.firebasedatabase.app`), режим **locked**.
   Для проекта `bimbleguard` URL `https://bimbleguard-default-rtdb.firebaseio.com`.
2. Прописать URL в `firebase.cfg` (не коммитится): `database_url="https://..."` в секции
   `[firebase]` (образец — `firebase.example.cfg`). Без ключа кооператива нет.
3. Задеплоить правила (владелец, не агент): `firebase deploy --only database`
   (или вставить `database.rules.json` во вкладку **Realtime Database → Rules**).
4. Ручная проверка клиента и боя на эмуляторе: `firebase emulators:start --only database --project demo-bimbleguard` (порт 9189), затем `godot --headless --path . --script res://tests/live_rtdb_emulator.gd`; на чистом эмуляторе (перезапустить его между прогонами).
5. Тесты правил на эмуляторе (Java 21): `cd firebase/rules-tests && npm install && npm test`
   (запускает эмуляторы Firestore и Database; `firebase.json`: `singleProjectMode: false`
   нужен, иначе эмулятор RTDB не принимает пространство имён тестов).
