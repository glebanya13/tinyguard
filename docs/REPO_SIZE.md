# Размер репозитория

Замер 2026-10-15 (`git count-objects -vH`, `git rev-list --objects --all`).
Историю git и LFS без решения владельца не трогаем: здесь только цифры и предложения.

## Цифры

| Что | Размер |
|---|---|
| Объекты в pack | ~25 МБ (сжатые) |
| Незапакованные (loose) объекты | ~128 МБ (лечится `git gc`) |
| Рабочая копия: `assets/` | 59 МБ (`assets/models` 49 МБ, `assets/store` 6,7 МБ) |
| `docs/screenshots` (110 PNG) | было 21 МБ, стало ~7 МБ после сжатия |
| Коммитов | 161 |

Сумма размеров всех версий блобов в истории, по расширениям (до сжатия git):
`.glb` ~325 МБ, `.png` ~34 МБ, `.gd` ~4,8 МБ, `.md` ~2,4 МБ, `.wav` ~2,2 МБ.
То есть историю раздувают **пересборки `.glb`**: каждая версия `level_N_terrain.glb`
и `level_N_decor.glb` весит 2,7-3,0 МБ и коммитится заново при любой смене генератора
карт (по 6 уровней x десятки пересборок). Скриншоты в `docs/screenshots` — вторая статья.

## Безопасные меры (уже сделаны или не меняют историю)

1. **Сжатие PNG в `docs/screenshots`** (`pngquant --quality=75-95`): 21 МБ -> ~7 МБ,
   подписи и интерфейс читаются. Сделано отдельным коммитом. Сами старые версии
   остаются в истории; выигрыш — для будущих клонов рабочей копии и новых коммитов.
2. **Не коммитить шум.** Пересобирать `.glb` и коммитить только когда изменился
   `assets/blender/build_*.py` или `levels.json`; одним коммитом со скриптом, не «на всякий случай».
   Скриншоты — только нужные, не серии (`lanes_01..06`) на каждую правку.
3. **`.gdignore` в `docs/`** (предложение): тогда Godot не создаёт `*.png.import` для
   скриншотов, и их не нужно коммитить. Файлы `.import` уже есть в индексе, поэтому
   вводить вместе с удалением старых `docs/screenshots/*.import` отдельным коммитом.
4. **`git gc`** локально (не меняет историю): `git gc --aggressive --prune=now`
   упаковывает loose-объекты (~128 МБ).

## Для владельца: решения, которые меняют историю

Не выполнять без явного решения владельца: после них все клоны надо переклонировать.

- **git-filter-repo**: убрать старые версии тяжёлых файлов из истории, например
  `git filter-repo --path-glob 'assets/models/level_*_*.glb' --invert-paths` (затем
  вернуть актуальные `.glb` одним коммитом) либо удалить `docs/screenshots` из старых коммитов.
  Делать на свежем зеркальном клоне, с резервной копией, затем force-push.
- **Git LFS** для `*.glb` и `docs/screenshots/*.png`: `git lfs track "*.glb"`; новые версии
  идут в LFS, репозиторий остаётся лёгким. Минусы: лимиты хранилища/трафика у хостинга,
  CI и клоны требуют `git lfs`, а `git lfs migrate import` тоже переписывает историю.
- Альтернатива: не хранить производные `.glb` вовсе, а собирать их в CI из `build_*.py`
  (Blender в CI). Противоречит правилу «`.glb` коммитятся» в CLAUDE.md, поэтому только по решению владельца.
