### Динамика

За два дня (2026-10-15 -> 2026-10-17) коммитов стало 161 -> 243 (+82), loose-объектов
128 -> 199 МБ. Рост даёт перегенерация `level_N_terrain.glb` / `level_N_decor.glb` при каждой
правке генератора карт (новые карты, дороги, облегчение моделей) и серии скриншотов
`docs/screenshots`. Старых версий `.glb` и `.png`, которых нет в HEAD: **339 блобов, 413,7 МБ
до сжатия, ~112 МБ в pack** (замер `git cat-file --batch-check='%(objectsize:disk)'`).

## Безопасные меры (не меняют историю)

1. **`git gc`** на основной копии (когда никто не работает в worktree): 231 -> ~153 МБ.
   Не `--prune=now` при живых worktree других агентов.
2. **Сжатие PNG в `docs/screenshots`** (`pngquant --quality=75-95`) — сделано, ~21 -> ~7 МБ.
3. **Не коммитить шум.** Пересобирать `.glb` и коммитить только когда изменился
   `assets/blender/build_*.py` или `levels.json`; одним коммитом со скриптом. Один набор
   скриншотов на изменение интерфейса, не серии по каждой правке.
4. **`.gdignore` в `docs/`**: тогда Godot не создаёт `*.png.import` для скриншотов.
   Вводить вместе с удалением старых `docs/screenshots/*.import`, отдельным коммитом.

## План очистки истории (для владельца; не выполнялся)

Ожидаемый результат: `.git` после очистки и `gc` ~ **40 МБ** (153 МБ - ~112 МБ старых версий).
Это оценка по сжатым размерам блобов; точное число даст только настоящий прогон на зеркале.
После шагов 2-4 **все клоны надо переклонировать**, открытые ветки/worktree агентов — пересоздать.

0. Заморозить работу: смержить/закрыть ветки агентов (их коммиты тоже перепишутся).
1. Свежее зеркало и резервная копия: `git clone --mirror <origin> bimbleguard.mirror`,
   рядом `cp -R bimbleguard.mirror bimbleguard.backup`.
2. Список удаляемых блобов — старые версии, которых нет в HEAD:
   `tools/slim_repo.sh --dump-ids strip_ids.txt` (по умолчанию `assets/models/*.glb`,
   `docs/screenshots/*.png`, `assets/store/*.png`). Затем в зеркале:
   `git filter-repo --strip-blobs-with-ids strip_ids.txt` (нужен `git-filter-repo`;
   текущие версии из HEAD остаются, дерево HEAD не меняется).
3. `git reflog expire --expire=now --all && git gc --prune=now --aggressive`,
   сравнить `git count-objects -vH` с таблицей выше.
4. `git push --force --mirror <origin>` — только по явному «да» владельца.
5. **Git LFS на будущее**: `.gitattributes` уже помечает `*.glb`, `*.png`, `*.wav` как binary;
   чтобы новые версии не раздували историю, заменить на
   `*.glb filter=lfs diff=lfs merge=lfs -text` (то же для `*.png`, `*.wav`) и `git lfs install`.
   Новые коммиты пойдут в LFS без переписывания истории; перенос уже существующих файлов —
   `git lfs migrate import --include="*.glb,*.png,*.wav" --everything` (ещё одно переписывание,
   делается вместо шага 2 либо после него). Минусы: квота хранилища и трафика у хостинга,
   `git-lfs` нужен на каждой машине и в CI (в нём сейчас не стоит: `which git-lfs` пусто).
6. Правило после очистки: `.glb` и скриншоты коммитятся только вместе с изменением генератора;
   `tools/slim_repo.sh` раз в неделю показывает, не вернулся ли рост.

Альтернатива: не хранить производные `.glb` вовсе, а собирать их в CI из `build_*.py`
(Blender в CI). Противоречит правилу «`.glb` коммитятся» в CLAUDE.md, поэтому только по решению владельца.
