# CLAUDE.md — правила проекта Bimbleguard

Лёгкая 3D Tower Defense для Android. Godot 4.3+, GDScript, Compatibility renderer.

## Стек и ограничения

- **Только Godot 4.x + GDScript.** Никакого C#, GDExtension, нативных плагинов.
- **Версия Godot: 4.7.2** (`config/features` в `project.godot`). `*.import` записаны в формате 4.7 и
  коммитятся; редактор 4.7 их больше не переписывает. Версию меняем только осознанным коммитом
  «обновление Godot» вместе с переимпортом (`godot --headless --import`) всех `*.import` и `*.uid`.
- **Рендерер:** `gl_compatibility` на всех платформах (`project.godot`). Не использовать
  возможности, недоступные в Compatibility: SDFGI, VoxelGI, объёмный туман, SSR, SSAO,
  compute-шейдеры.
- **Платформа:** Android, альбомная ориентация, ввод касанием (мышь эмулирует тач).
- **Сеть — только модуль `Online`** (`scripts/online.gd`, Firebase REST: анонимный вход,
  рекорды осады, облачное сохранение; см. `docs/FIREBASE.md`). Игра обязана полностью
  работать офлайн и без `firebase.cfg`. План Firebase — Spark: **без Cloud Functions**, вся
  серверная гарантия — в `firestore.rules` (тесты: `firebase/rules-tests`). Кооператив (2 игрока, lockstep через Realtime Database, только REST; владелец разрешил 2026-10-14, план — `docs/MULTIPLAYER.md`) — через модуль сети; игра обязана работать и без него. Без аналитики и рекламных SDK, без своих серверов и P2P/GDExtension.
- **Без внешних ассетов** из магазинов и сети без явного разрешения владельца;
  всё — примитивы Godot или собственные модели из `assets/blender/`.
- **Модели генерируются скриптами** `assets/blender/build_*.py` (см. README там).
  Править скрипт и пересобирать, а не редактировать `.glb` руками. Цвета — только из
  `PALETTE`; все модели используют общий материал `assets/materials/tg_palette.tres`.
- **Звуки генерируются** `tools/gen_sounds.py` (детерминированно); правьте генератор,
  а не WAV.

## Структура

| Каталог | Содержимое |
|---|---|
| `scenes/` | `.tscn` игровых сущностей и уровней (`main.tscn` — точка входа) |
| `scripts/` | `.gd`, по одному скрипту на сцену/систему |
| `resources/` | `.tres` с данными: башни, враги, волны (`Resource`-классы) |
| `ui/` | сцены интерфейса, `Theme` |
| `assets/blender/` | исходники `.blend` |
| `assets/models/` | экспорт `.glb` |
| `assets/materials/` | общие `StandardMaterial3D` `.tres` |
| `tools/` | вспомогательные скрипты (Python), не входят в сборку |

## Стиль GDScript

- Следовать официальному style guide Godot: **табы** для отступов, `snake_case` для
  файлов, функций и переменных, `PascalCase` для `class_name` и узлов, `CONSTANT_CASE`.
- **Статическая типизация везде:** `var hp: int = 10`, `func f(x: float) -> void:`.
- Порядок в файле: `class_name`, `extends`, docstring `##`, сигналы, enum, константы,
  `@export`, публичные переменные, приватные (`_name`), `@onready`, встроенные колбэки,
  публичные методы, приватные методы.
- Связь «вниз» — вызовом методов, «вверх» — сигналами. Не тянуться к родителю через
  `get_parent()` и абсолютные пути `/root/...`.
- Числа баланса — в `.tres`-ресурсах или `@export`, не магическими числами в коде.
- Autoload (синглтоны) — только при реальной необходимости, максимум 1–2. Сейчас один:
  `Online` (сетевые запросы должны переживать смену сцен). Обсуждать перед добавлением.

## Производительность (мобильные)

- Цель: 60 FPS на среднем Android 2020+ года, < 100 draw calls в кадре.
- Бюджеты треугольников — в `docs/ART_GUIDE.md` (враг ≤ 2 000, башня ≤ 4 000,
  уникальный герой ≤ 12 000, кадр ≤ 100 000). Замерять draw calls через
  `RenderingServer.get_rendering_info()` после изменений сцены.
- Статичный декор уровня запекать в общий меш; мелочь — без отбрасывания теней.
- Один `DirectionalLight3D` с тенями; без динамических `OmniLight3D` в массовых сущностях.
- Переиспользовать материалы (общие `.tres`), не создавать материал на каждый инстанс.
- Много одинаковых объектов → пул узлов или `MultiMeshInstance3D`.
- Не выделять память в `_process` без необходимости; таймеры — через `Timer`/`SceneTreeTimer`.

## Сцены и файлы

- `.tscn`/`.tres` — текстовые, коммитятся. `.godot/` — кэш, не коммитится.
- Файлы `*.import` рядом с ассетами **коммитятся** (настройки импорта).
- Godot 4.4+ создаёт рядом со скриптами и ресурсами файлы `*.uid` — их тоже
  **коммитить**, иначе ссылки по UID будут пересоздаваться на каждой машине.
- При ручной правке `.tscn` поддерживать корректность `load_steps`, `id` и путей `res://`.
- Blender: коммитить скрипты и `.glb` (+ `.glb.import`); `.blend` из `--blend`
  лежат в `assets/blender/out/` и не коммитятся.

## Проверки перед коммитом

1. `python3 tools/validate_project.py` — структура и ссылки.
2. Если Godot установлен: `godot --headless --path . --import`, затем запуск сцены
   без ошибок и предупреждений в выводе.
3. `tests/run_all.sh <godot>` — headless-тесты (геймплей, проходимость, пауза) на всех уровнях.
4. `gdlint scripts/*.gd tests/*.gd` и `gdformat --line-length 100 --check` — стиль.
5. Изменения баланса — `python3 tools/balance_sim.py`; геймплея — запуск сцены и проверка руками.

**Не утверждать, что проект запускается, если запуск не был реально выполнен.**
